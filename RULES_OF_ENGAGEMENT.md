# Triagely – Rules of Engagement

## 1. Authorised scope

Testing is restricted exclusively to the local
Triagely instance operated by the project owner.

The GitHub repository is provided for source-code
review and assessment.

No external systems are included in the testing scope.

## 2. Data protection

- Do not enter real personal data.
- Use synthetic or demonstration data only.
- Do not expose passwords, API keys or access tokens.
- Do not publish sensitive information.

## 3. Testing restrictions

- Test only the local Triagely instance.
- Do not scan external websites or infrastructure.
- Do not test third-party services.
- Do not perform destructive testing.
- Do not access systems outside the agreed scope.

## 4. Third-party software

If a potential vulnerability is discovered in software
developed by another party:

- Do not report it to the vendor independently.
- Do not publish the finding.
- Discuss it with the project owner first.
- Obtain permission before any further action.

## 5. Findings and disclosure

All findings must remain private.

Do not publish vulnerability reports, screenshots
containing sensitive information, or security findings
without discussing them with the project owner first
and obtaining approval.

## 6. Assessment baseline

The agreed kickoff baseline is identified by:

Git tag: kickoff-2026-10-30

The tagged version is the version to be assessed.

Subsequent changes must be distinguished from
the original assessment baseline.

## 7. Responsible conduct

All testing must remain within the agreed scope.
If the scope is unclear, stop testing and consult
the project owner before proceeding.
